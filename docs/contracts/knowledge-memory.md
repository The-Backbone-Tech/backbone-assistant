# knowledge-memory contract (DRAFT 0)

**Owner:** integrator (core).

**Layer:** L0.

**Status:** have. The logbook and the tiers are gaps.

## Purpose

Accepted knowledge changes only through promotion. Memory is private and a draft until it is promoted. Trust is fixed at ingest.

## Owns

- accepted knowledge, with verbatim quotes and provenance;
- private memory;
- retractions;
- trust marks;
- the opt-in logbook or why-store [new].

## Provides

- `gov.request_promotion` / `gov._promote`;
- `gov.retract_knowledge`;
- `gov.forget_memory`;
- scoped search.

## Consumes

- mandates-decisions (an independent checker);
- identity-tenancy.

## Rules

- There is one door: promotion. No agent can be a source for its own promotion.
- Marks only rise.
- A retraction propagates to citing drafts and briefs (R-MEM-01).
- Tiers: originals (work-material, read-only bytes) → working copies (work-material) → accepted (here). This answers R-MEM-TIER-01.

## Built: the private memory data folder

Built in `packages/platform` (`src/memory/store.ts`, `src/memory/learn.ts`, `src/memory/imports.ts`, `src/composition/memory.ts`). It is the **private memory** tier only: nothing here is accepted knowledge, and there is no promotion through it.

- Plain markdown under the data folder's `memory/`: the person's `instructions.md`, `projects/<id>.md`, `topics/<slug>.md` (one line per memory, ending in an id marker), `daily/<date>.md` and `index.md`. What a line came with (origin, sources) is kept by id beside them. The files win: an outside edit is read back, a line added by hand is the person's, and a removed line is forgotten.
- Consolidation persists replacement provenance (and, for a change made by itself, its undo record) before replacing or taking out the originals together in one atomic topic write. Failed writes leave the originals and proposal, or the sourced replacement; a retry recognises that replacement by its proposal id and provenance if proposal cleanup was interrupted. The exact topic snapshot is checked again after staging, so an outside edit during staging refuses the merge and preserves the edited lines and proposal. **Accepted limit:** an uncooperative editor that writes the Markdown directly can still race between this final snapshot check and the durable writer's rename; no filesystem compare-and-swap is claimed. This limit concerns direct external file writes. The merge itself holds the host's data folder lock. Disposable write-boundary, retry, provenance and separate-process edit regressions are in `packages/platform/test/memory-recovery.test.ts`; they do not establish an actual full-disk or power-loss run.
- Every engine is given it through the engine port's `TurnRequest.recall()`, which the engine calls once, at the moment it builds the model input (Pi before its first request, Codex in `prompt()` after staging), so a source withdrawn while the engine prepared is already out. It returns `history` (the earlier conversation less any answer a withdrawal since the turn started has reached; it replaces `TurnRequest.history`; Pi reads it after resolving the credential, right before its first request), `instructions` (the person's and the project's own words, where the engine's instructions go) and `memory` (the lines that bear most on the turn, as reference data that cannot change what the agent may do). Pi puts instructions in its system prompt and memory beside the person's words; Codex native frames both in its staged prompt, beside its own memories, which stay on. The stand-ins call no model and are given nothing. A recalled line's sources are recorded among the turn's reads before any wait, and only lines whose sources were recorded may be given, so the withdrawal mechanism covers what the turn makes from it. `Turn.memory` records ids only; the words stay in memory.
- Ranking (`memory/rank.ts`): BM25 over light word stems, with a near miss (one edit, in words of five letters or more) at half weight. Among equally relevant lines, provenance decides first (personal, imported, then untrusted), with newest first within each tier. When the person names an embeddings model on this computer (`memory.meaning.put`, an OpenAI-compatible `/embeddings` at 127.0.0.1 or [::1], an address and never a name, since `localhost` is whatever the resolver says), lines and the turn's words are embedded there and cosine similarity is merged with the words (`memory/embeddings.ts`). Nothing is started or downloaded, and no redirect is followed. What may be sent (memory's lines, its credentials) is read again before each request and before the cache is written, so a line forgotten, withdrawn or found to hold a credential meanwhile is neither sent nor kept. Vectors are cached in `memory/.vectors.json` by text hash for that route only, pruned when a line is forgotten, changed or withdrawn, and never written after the route was cleared or changed. One similarity runs at a time. A route that fails or answers out of shape leaves recall to the words. Mid-turn, an engine may also look memory up itself (engine port `searchMemory`; Pi and Codex offer `memory_search`, ACP offers `search_memory`, when the Host supplies the method): the same ranking, at most 8 lines, none holding a known credential; each line's sources are recorded among the turn's reads before its words come back, a line whose source was withdrawn by then is not given, and the chosen lines join `Turn.memory.used` in the same save as their reads, before any word is handed over and kept when a resumed turn recalls again (the record may name a line kept back by the last checks, never the reverse); after that save memory checks credentials and the turn checks withdrawal with no wait before the words go. Their sources are read as never withdrawn (memory gives no line whose source ever was), so any withdrawal since counts; the credential check runs after they are recorded; a turn that ended meanwhile is given and records nothing; read-only turns (reviewers, judges) are not offered it. Accepted limits, as for recall at the start of a turn: an imported or hand-written line has no sources to enforce, and memory's sources are not write dependencies, so a later version of a source does not hold a write made from an older line. Accepted limits: a local server the person names may itself forward what it is sent, as with a local model route; and it decides the similarities, so it can choose which existing lines (and only those, under the same source and credential rules) are recalled.
- **Consolidation and learning, by a model's judgement** (`memory/judge.ts`, `createMemory` in `composition/memory.ts`). A pass runs once a day, on `memory.consolidate`, and after a turn that proposed lines. It asks one model turn through the data folder's configured engine route (the host's `judge`: its engine on `routes.resolve()`, never a fixed engine; stopped when the host closes; no model set up means no pass). The turn is bare (`TurnRequest.bare`, sent only to an engine that declares `bare`): Pi gives it no tool at all; native Codex runs it in the contained filesystem with its shell off, no web search, no client tools, nothing staged and nothing imported, forces off every feature Codex reports on in `codex features list` (its defaults as well as the person's config) but `code_mode_host` and `skip_host_skill_discovery`, reads that effective list back with the same overrides and refuses the turn unless the shell is off and nothing else is on (on 0.165.0 removed-stage flags and `unified_exec`, which only chooses how the shell runs, cannot be switched off and are accepted), runs on a copy of the model catalog Codex reports (`codex debug models`) with every model's tool choices set to none (`tool_mode` direct, no multi-agent version, no apply-patch, clock or search tool), loaded through `model_catalog_json`, since on 0.165.0 the catalog, not the features, adds code-mode `exec`, `wait` and the sub-agent tools; proves it before the real request by starting the same settings against a loopback stand-in provider (a random secret path, only a POST naming the expected model, closed after it) and refusing the turn if the one request Codex would send offers any tool, in `tools` or as an input item (no credential is sent there); checks the configuration as the app server reads it back, the catalog included, and that the catalog's bytes (written in an owner-only folder) still match the digest the preflight proved, after the read-back and before the turn starts (a same-user process is outside this boundary), and fails the turn on any reported item other than the prompt, reasoning and the answer (an allowlist, so a tool type not known yet fails it too). The model is shown up to 150 lines and proposals as data, by short handles, each marked with its editing owner and computed provenance tier, none holding a known credential and none already in a waiting change, and answers with changes: merge lines of one topic, supersede older lines by a newer one, retire a stale one, keep or hold a proposal, each with a reason and any of the person's lines it contradicts. An answer is checked before anything happens: known handles only, each used once, one topic per change, no credential in new words; anything else is dropped. The person's own words are every line not learned by an engine (added by hand, written back from their message, imported, or kept by them), and any engine line the person has edited, through `memory.put` or in the Markdown (an engine line keeps the words it was written with, and differing words make it the person's). A change that takes out any of them, or that the model says contradicts them, waits under Proposed with what was judged and why; so does any change that produces new words: only retiring or superseding an engine's lines, keeping an engine's proposal word for word, and a merge whose words are exactly one of the engine lines it replaces (a dedupe, sources joined) are done by themselves. A merge with other words carries the sources of every line and proposal its pass showed. A proposal the model does not mention also waits. A reason holding a known credential is withheld before it is saved, and a change whose new words, removed lines or snapshots hold a credential known when it is saved is not made at all; a pass saves nothing if the name or id of any source it showed is such a credential (every occurrence is checked, before sources are deduplicated), and a change is not made if the lines it takes out, as they are when it is saved, carry such a source. A person keeping a proposal that is already a line makes that line theirs. Anything else is done at once, with its undo record (`memory/.changes.json`, the last 50: what it added and every line it took out, whole) durable before memory changes; `memory.undo` puts the taken lines back with their ids and records, then takes the added line out; it refuses if the person has since changed that line, or if a line it would put back holds a credential known now. An engine's line kept this way keeps its turn's sources; a merged line carries every source of what it replaced. Every record a pass saves (an undo record, a held change, its reason and snapshots) depends on the sources of everything that pass showed the model; if any was withdrawn by the time the answer is applied under the data folder lock, nothing of the pass is saved. A withdrawal purges as before, takes a withdrawn line out of every undo record with the words of a replacement that left with it (a keep's record leaves entirely), redacts the reason of an undo record that depended on it, and removes any held change that depended on it, which can then no longer be kept. A line is written with its record first, so an interruption never leaves a line without its origin and sources. Undo records are rewritten only under the data folder lock; `memory.get` reads them, and settles memory under the lock. The answer is applied under the data folder lock to exactly the lines the model saw; a line changed meanwhile is left. Passes run one at a time. Tests use a scripted judge (`testing/memory-model.ts`, word rules that prove the plumbing, not judgement). **Accepted limits:** whether a line contradicts the person is the model's judgement; the deterministic rule only guarantees that their own lines are never taken out without them, and an undo is the remedy for a wrong automatic change. A pass sends memory's lines to the configured route, as recall already does.
- An engine may propose a line mid-turn (`propose_memory`, engine port `proposeMemory`; Pi, Codex and ACP offer it to turns that are not read-only when the Host supplies the method). It is held in `memory/.proposed.json`, never recalled or searched until kept, and judged when the turn ends: kept by itself or held for the person (`memory.proposal.decide`; kept by the person, it is theirs from then on). Its sources are the proposing turn's reads and attachments; a turn whose reads are unknown or withdrawn proposes nothing, a proposal leaves when any source is withdrawn, a credential is refused when proposed and again when kept, a line already remembered or waiting is not added twice, and at most 5 per turn and 50 in all wait.
- Write-back from a finished turn keeps only what the person said in their own message: "remember…", a standing preference, a correction, a fact about their own things. Nothing is stored or handed to a model that holds any value the credential store holds (sealed or Keychain, however short), a known credential format, or a credential named and given; learning also skips any sentence that names one. If the stored values cannot be read, nothing is stored or given.
- A line made in a turn carries the documents that turn was given; a line kept again joins its new sources to the old, and a line whose source is already withdrawn is not kept. A withdrawal purges at once, under the data folder lock: the line leaves its topic file, its daily note, its record and the index, and does not return on restore (R-MEM-01 for memory).
- Imports from Codex (`.codex/memories` in the operating system home folder only), Claude (`CLAUDE.md` and auto memory) and a markdown file the person names are read-only copies with the source path on each line. Each named root is anchored to the operating system home folder: no folder below that home is a link, and the root's real location is exactly the expected one. Every read stays inside that real location at every level, through no linked folder, from a single-link file, read from the handle that was checked. Node has no `openat`, so after each read the root and the file are checked again (real location, device and inode) and a swapped folder fails closed. A named file in a place that holds credentials (`CREDENTIAL_PATHS`, shared with the Codex engine) is refused.

**Accepted limits** (cold review, round 2). Credential detection beyond the values the store holds is heuristic: a credential the store never held, or no longer holds, in a form the check does not know, can pass. A skill's text is model input that can steer behaviour; it is labelled as reference data and changes no permission, but the label does not enforce taint.

## Memory off for a task

Before starting a new task in the app, the person can turn Memory off. The choice is saved with that draft and then with every turn's settings (`TurnSettings.memory: 'off'`); another task defaults to memory on. Off tasks receive no personal or project memory instructions, recalled lines, learned skills, memory search or memory proposal tool, and make no memory write-back, correction proposal or automatic skill draft. Explicit drafting from their finished turns is refused. The memory composition checks this setting before reading credentials, embeddings or memory files. Child settings and side questions retain the restriction, including after restart. The process API line and MCP task selection preserve the setting and refuse unrecognised values; the confirmation names memory off. Off recall also withholds the role and plugin-agent listings it normally carries; explicit role selection keeps its own checks. Each turn says that memory is off. The switch covers the private memory and learned skills managed by Backbone. It does not erase the conversation or change an external engine's own memory settings. An omitted setting preserves the existing behaviour. Focused tests: `packages/platform/test/memory-controls.test.ts`; app proof: `packages/surfaces/app/e2e/memory-controls.electron.spec.ts` (fresh installed execution is the integrator's responsibility).

## Private memory trust and narrow attack signals

The boundary is the trust tier computed from the stored provenance record, never the scanner or a label inside a line. All recalled memory, including personal statements and a line the person explicitly includes after a warning, is reference data and cannot give authority. Recall quotes each line as a JSON string after its tier to distinguish content from its label. Ownership for editing is separate from trust. Imported or derived words do not become personal merely because someone edits them. An engine with independently authorised access to the plain Markdown can still create new lines that look like direct human edits; the memory API cannot authenticate external filesystem authorship.

The local rules in `packages/platform/src/memory/scan.ts` are a signal that withholds only clear, high-confidence attack patterns. They must almost never block ordinary memory. They are not an injection detector with complete coverage and cannot establish that a line is safe. The ten rules cover direct imperatives to discard previous instructions, override the assistant's own rules, disable its safety policy, or void its system instructions; assistant directives hidden in HTML comments, hidden elements or Markdown comments; forged model-protocol role delimiters; outbound URL queries containing data placeholders; and explicit private-data transfers to HTTP destinations. Complex patterns receive at most the first 1,024 UTF-16 code units, both before and after NFKC expansion. The rest of a long direct-file line is outside this heuristic window; this is not a safety guarantee. The fixed window bounds regex work independently of file-line size. Each rule has its reason beside it and a proving example in `packages/platform/test/memory-scan-corpus.ts`.

Matching uses a separate NFKC copy with invisible format characters (including bidi controls and soft hyphens) stripped. Such characters alone cause no refusal. Storage preserves emoji joiners and RTL text, including valid emoji tag flags. Engine-facing copies spell invisible format and Unicode default-ignorable characters as visible Unicode code-point notation: initial recall, mid-turn tool results, judge input (including pending proposals), local embedding input and both MCP read representations. Adapter replay also makes old assistant answers visible after its existing credential scrub/check; human message bytes and stored history remain unchanged. U+2028/U+2029 also become visible, so content cannot add a visual item boundary. Raw words remain the inputs to credential checks, snapshot comparisons and provenance; only the outgoing copy is formatted. Embedding cache keys use that outgoing representation, preventing reuse of an older vector for hidden text. The Memory page lets the person reveal these characters without rewriting their words. The corpus test includes all 16 examples from the security review and ordinary Spanish, Hebrew, Arabic, Chinese and emoji memories. The attack corpus records expected outcomes, including deliberately **not caught** paraphrases, cross-script homoglyphs, spaced letters, leetspeak, base64, non-English attacks, split-line attacks, interrupted instruction phrases, authority claims, email transfers, secret-disclosure requests without an outbound URL, and prose describing URL substitution. These limits are why provenance and authority checks remain necessary.

Every read rescans existing text with the current rules. A withheld line stays on disk and on the Memory page with its category, even while the person searches; it is excluded from recall, search results, embeddings and consolidation candidates. The person can edit or forget it, or choose **Use as reference**. This uses the existing `memory.put` operation to save the existing text unchanged. Only this unchanged save (after the API's normal whitespace folding) overrides the signal for the exact stored topic and text, durably by hash, preserving the original bytes; an edit to different unsafe words is still refused. The warning then says it was included by the person. Its stored trust and data-only framing do not change. A changed topic or text invalidates the override. Known credentials and withdrawn sources remain excluded independently. This path retains the existing API limit of 1,000 characters after whitespace folding; longer direct-file lines can be edited or forgotten, and a dedicated override for them needs the deferred composition handler. No new authority or engine tool is added.

File and text imports skip individual credential or attack-pattern lines and continue importing the rest, retaining each admitted line's import provenance. Their receipt reports the original source and one-based Markdown line number with a category, without echoing rejected payloads or destination URLs. The Memory page shows this report. Read failures still fail the operation; they are not disguised as skipped lines.

Proposal admission scans normalized words and the raw topic before writing the pending file. Legacy unsafe pending proposals remain visible with their category, but never enter consolidation input or consume the active waiting caps. Their category is recomputed from current words and rules on every read and is never persisted as a proposal decision. Stored unsafe entries are excluded from consolidation even when the person included them for recall. Each judgement is scanned before staging an undo or touching memory, including the exact normalized topic passed to storage, so one refused change cannot stall other changes or later passes. Only typed scanner refusals become INVALID receipts in put, proposal acceptance and undo; unrelated storage failures remain failures. Undo scans its whole restoration batch before any mutation and keeps the replacement and undo record intact on refusal. Learning skips refused lines independently and continues corrections and skill drafting. Child worker briefs are engine words and never enter personal-message learning.

Accepting an engine proposal transfers editing ownership, but preserves its untrusted provenance. Novel model-authored merges carry the weakest trust and sources of everything shown to the judge, with an untrusted floor; verbatim deduplication also retains any lower trust shown to that judgement. These marks survive proposal acceptance, undo and reopening. The bare consolidation judge receives the computed trust on each line and proposal separately from editing ownership; accepted engine words, imports and sourced claims are not presented as the person's authored statements. Its prompt treats lower-trust claims as reference data, never instructions or permission. Public memory search, including the API-line and MCP read path, returns no results when the current credential store cannot be read after the similarity wait. Mid-turn search returns each stored tier and renders every value as a visible JSON string beside its own tier; the labels grant no authority. Source withdrawal and credentials are checked again after recording the reads.
