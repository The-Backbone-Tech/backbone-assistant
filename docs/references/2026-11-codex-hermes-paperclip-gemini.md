## Products

### OpenAI Codex and ChatGPT (Work, dots, enterprise administration)
- **Current version:** Codex CLI 0.167.0, 6 November 2026 (C1, CS). ChatGPT for iOS 1.2026.300, 2 November 2026 (C1). Alphas of 0.169.0 were being cut on 9 November (CS).
- **Licence:** the CLI repository is Apache-2.0 and contains the Rust core, the terminal interface, the app-server, both SDKs, the sandbox crates and the automatic-review ("guardian") crates (CS, source). The desktop app, cloud tasks, dots, Work Cloud and the Admin Console have no public source (not found in CS).
- **Last 60 days:** GPT-5.5 retired from Codex for ChatGPT sign-in on 14 October 2026 (C12); 0.166.0 (29 October) made `[network_proxy]` the canonical managed-network key (C7) and added `codex queue --resume`; 0.167.0 added the agent command centre (`codex agents`), managed command checkpoints that need a fresh human decision, and Guardian review of recorded commands (CS release notes); October work routed state-changing multi-agent calls through automatic review (C1).
- **Architecture:** (1) One Rust core (`codex-rs/core`) runs the agent loop. (2) Every client (terminal UI, desktop app, IDE extension, SDKs) talks to it through the app-server, JSON-RPC 2.0 over stdio, WebSocket or a Unix socket, with three primitives: thread, turn, item (C18). (3) Thread history is JSONL "rollout" files plus a local state database (C18; `codex-rs/state`, `thread-store` in CS). (4) The model is called over the OpenAI Responses API; other providers are declared under `[model_providers.*]` (C31). (5) Shell tools run inside an operating-system sandbox chosen per platform (C5). (6) Approval requests travel from server to client as JSON-RPC requests (C18). (7) Cloud tasks run in per-task virtual machines started from a published environment snapshot (C21). (8) ChatGPT Work adds a cloud orchestrator that can call a connected computer as an executor (C29). (9) Company policy arrives as `requirements.toml` from the cloud, a device-management profile or a system file (C7). (10) dots are persistent assistants layered on the same execution and permission machinery (C15, C29).

### Hermes Agent (Nous Research)
- **Current version:** v0.23.0 "The Hearth Release", 5 November 2026 (HS). Licence MIT (HS). Python, about 262k GitHub stars on the day read.
- **Last 60 days:** v0.22.x through October; v0.23.0 put one gateway in charge of every session so the command line, terminal interface, desktop app, editors, bots and cron share it, and added the Webapp, the desktop workspace served to a browser from the user's own gateway (HS release notes, vendor claim for scope; H17 documented).
- **Architecture:** (1) `AIAgent` in `run_agent.py` with the loop in `agent/conversation_loop.py` (H1). (2) Entry points: CLI, terminal interface, long-running gateway (`gateway/run.py`), ACP server for editors, OpenAI-compatible API server, cron scheduler, batch runner (H1). (3) State is SQLite at `$HOME/.hermes/state.db` with FTS5 search; configuration is `$HOME/.hermes/config.yaml` and `.env`; each profile has its own home (H11, H1). (4) The model is called through a provider resolver with three wire modes: `chat_completions`, `codex_responses`, `anthropic_messages` (H1). (5) Tools register in a central registry and are grouped into toolsets (H1). (6) Shell commands run in a selectable terminal backend: local, Docker, SSH, Modal, Daytona, Vercel Sandbox, plus plugin backends (H1, H2). (7) The gateway hosts 25+ messaging adapters and ticks cron every 60 seconds (H12, H7). (8) Desktop is an Electron shell over the same runtime; it can attach to remote gateways or Hermes Cloud (H17). (9) A kanban board in SQLite coordinates separate worker processes (H10). (10) Plugins extend memory, context engine, providers, platforms and terminal backends (H1).

### Paperclip
- **Current version:** v2026.1106.0, 6 November 2026 (P20). Licence MIT (PT, repository metadata). TypeScript server and UI; the Runner is Rust (P8).
- **Last 60 days:** the Paperclip Runner became the default for new Claude, Codex, OpenCode and Pi agents; GitHub Copilot added as a harness; the Pipelines experiment was removed; model-backed screening of tool results for prompt injection; export of agent logs and traces to Braintrust or an OTLP endpoint; workspaces that clean themselves an hour after a task tree finishes (P20, vendor claim unless cited elsewhere).
- **Architecture:** (1) A control plane, not an agent: Express 5 REST API on Node 24, React 19 UI, `paperclipai` CLI (P1). (2) PostgreSQL 17 through Drizzle; an embedded database for zero-configuration local mode (P1). (3) Every record belongs to one company (P1, P16). (4) Agents are external harnesses reached through adapters (`claude_local`, `codex_local`, `process`, `http`, and more in `paperclip:packages/adapters`) (P1, PT). (5) Work happens in finite "heartbeat" runs: a trigger fires, the adapter starts the harness, the harness calls Paperclip's REST API to check out a task and report (P1, P13). (6) Paperclip never calls a model itself; the harness does (P1). (7) The Runner (`paperclip-runnerd`) runs harnesses outside the server over an authenticated WebSocket protocol and treats every result as an untrusted claim that the server validates (P8). (8) A tool gateway governs MCP and app connections with grants, policies, approvals and an append-only call log (P4). (9) Remaining work between runs lives in database rows that a scheduler turns into new runs (P19). (10) Sandbox providers (E2B, Cloudflare, Daytona, Modal, Novita, Kubernetes and others) are plugins (P21, PT).

### Gemini CLI
- **Current version:** v0.67.0, 4 November 2026; preview v0.68.0-preview.0 the same day (G18, repository releases). Licence Apache-2.0.
- **Status change that matters:** since 18 June 2026 the README says Gemini CLI is maintained for Gemini Code Assist Standard and Enterprise and Code Assist for GitHub on Google Cloud; free and Google AI Pro and Ultra access moved to Antigravity CLI, and Gemini CLI is not tuned for the Gemini 4 series (G1, documented). Treat it as an enterprise maintenance line, not Google's lead agent.
- **Architecture:** (1) TypeScript monorepo: `gemini-cli:packages/cli` (terminal interface), `packages/core` (agent loop, tools, policy engine), `gemini-cli:packages/sdk`, `gemini-cli:packages/a2a-server` (experimental), `gemini-cli:packages/vscode-ide-companion` (PT of that repository). (2) Sessions are files under `$HOME/.gemini/tmp/<project_hash>/chats/` (G7). (3) Settings merge four JSON layers: system defaults, user, workspace, system overrides (G5). (4) The model is Gemini through a Google sign-in, an API key or Vertex AI (G5, G16). (5) Tool calls pass a policy engine before execution (G2). (6) Sandboxing is optional and wraps the whole CLI in Seatbelt or a container (G3). (7) Subagents are exposed to the main agent as tools with their own context (G6). (8) Extensions bundle MCP servers, commands, skills, subagents, hooks and policies (G12). (9) Headless mode prints JSON or JSONL for scripts (G9). (10) OpenTelemetry is built in (G10).

## What an open platform should take

1. Parallel work: **replicate cleanly** Hermes's split between cheap in-process children and a durable board with atomic claims and leases. MIT, so code may be reused with attribution.
2. Sessions: **adopt** the Codex app-server thread model as a compatibility target. Apache-2.0 permits embedding; keep the NOTICE file.
3. Goals: **adapt** the Codex goal runtime (state, budget, no-progress classification, completion audit) and add Hermes-style external gates so completion does not rest on the model's own word. Apache-2.0 and MIT both allow this.
4. Command line: **replicate** JSONL events, schema-constrained final output and a policy-check command. No licence issue; these are interface conventions.
5. Messaging: **integrate** Hermes's gateway rather than rebuilding 25 adapters. MIT.
6. Memory: **replicate** the small, frozen, user-visible core with staged writes, and **adapt** idle-time extraction and consolidation. Ideas only, or MIT and Apache code.
7. Skills and MCP: **adopt** the agentskills.io format and MCP; **replicate** quarantine scanning, hash-bound hook trust and per-server spend limits. Open standards.
8. Proactivity: **replicate** wake gates and script-only jobs (no model cost when nothing changed) and Paperclip's signed, idempotent webhook triggers. MIT.
9. Self-improvement: **adapt** Hermes's curator, and **build** the missing piece none of the four has: measuring whether a learned skill improves outcomes.
10. Models: **integrate** many providers as Hermes does; keep harness-level adapters as Paperclip does. MIT.
11. Permissions: **adopt** the Codex sandbox crates and rule language where possible (Apache-2.0), **replicate** the reviewer-agent pattern with fail-closed behaviour and a class of rules only a human can satisfy, and **replicate** Paperclip's rule that an unknown write outcome is recorded as such and never re-sent automatically. This is the family where reuse saves the most work and where a weaker copy would be dangerous.
12. Workspace: **integrate** existing computer-use and browser tooling; **defer** locked-device use, which needs platform-specific signed components.
13. Connectors: **replicate** Paperclip's vault, grant and audit model around MCP. MIT.
14. Deployment: **replicate** Hermes's "gateway serves the workspace to any browser" for phone access before building native apps; **defer** store packaging.
15. Licence: **adopt** a permissive licence for the whole product, as Hermes and Paperclip do; a closed desktop or admin layer is what the open references avoid.
16. Identity: **build** group-assigned roles and SCIM on a standard OpenID Connect base; none of the open products has it, so there is nothing to reuse.
17. Audit: **replicate** Paperclip's append-only per-call record and **build** an export stream; be as explicit as OpenAI is about what the record does not cover.
18. Administration: **replicate** the Codex model of defaults versus requirements, layered sources, a signed cache and fail-closed start; **adapt** Hermes's leaf-level key pinning. Apache-2.0 and MIT.
19. Fleet: **defer** until identity and managed policy exist; then **replicate** Codex's use of platform channels (managed preferences, a system file, a store package).
